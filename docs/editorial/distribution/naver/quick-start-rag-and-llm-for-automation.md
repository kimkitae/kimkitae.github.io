# 자동화 스크립트를 찾는 시간을 줄이는 RAG 활용법

자동화 코드는 자주 바뀝니다. 함수 이름과 파라미터가 조금씩 달라지고, 예전 예제를 찾으려면 저장소를 뒤져야 합니다. RAG(Retrieval-Augmented Generation)는 이 검색 비용을 줄이는 데 쓸 수 있습니다.

## RAG는 학습이 아니다

RAG는 모델을 다시 학습시키는 기술이 아닙니다. 스크립트를 청크로 나누고 임베딩해 벡터 인덱스에 저장한 뒤, 질문과 가까운 청크를 검색해 프롬프트에 넣는 방식입니다. 저장소를 다시 인덱싱하면 최신 코드를 참조할 수 있습니다.

## 로컬 실행에 대한 오해

Apple Silicon Mac은 GPU와 Metal 가속을 사용할 수 있습니다. “맥에는 GPU가 없다”는 설명은 정확하지 않습니다. 다만 모델 크기와 컨텍스트가 커지면 메모리 요구량도 커지므로 작은 모델부터 시작하는 편이 좋습니다. 원문에는 LoRA 학습 시 메모리 사용이 130GB였다고 적혀 있지만, 이 값은 환경과 설정에 따라 달라집니다.

## 데이터와 검색 품질

모델보다 데이터가 중요합니다. 주석이 없고 이름이 모호한 스크립트는 검색도 어렵습니다. 원문은 검색 결과에 파일 경로와 미리보기를 함께 보여 주고, Slackbot에서도 LLM이 참고한 검색 결과를 노출했습니다. 생성된 코드의 자동 실행은 범위에서 빼는 것이 안전합니다. 이 글의 코드는 구조를 설명하기 위한 스케치입니다.
