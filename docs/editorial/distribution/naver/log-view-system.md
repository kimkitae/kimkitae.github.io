# 자동화 도구가 늘어날 때 로그를 한곳에서 보는 방법

자동화 도구가 여러 개로 늘어나면 “지금 어디서 실패했는지” 확인하는 일이 병목이 됩니다. New Relic, Datadog, Grafana 같은 도구가 이미 있지만, 간단한 로그 한 줄을 보려고 전체 관측 시스템을 붙이는 것은 과할 때가 있습니다.

## 작은 LogViewer의 구조

API 서버가 로그를 Kafka 토픽으로 보내고, 별도 컨슈머가 MariaDB에 저장하면서 Redis Pub/Sub으로 실시간 전달합니다. 웹 UI는 WebSocket으로 로그를 받고, 새로고침할 때만 DB에서 최근 내역을 가져옵니다. 수집과 표시를 분리한 것이 핵심입니다.

## 지금 다시 만든다면

FastAPI의 `@app.on_event("startup")` 대신 `lifespan` 컨텍스트를 사용하는 편이 좋습니다. 연결과 정리를 한곳에 모을 수 있고 테스트하기도 쉽습니다. 로그량이 크지 않은 내부 도구라면 Kafka보다 단순한 큐가 나을 수도 있습니다. 도구는 문제 크기에 맞춰야 합니다.

## 운영에서 먼저 정할 것

인증번호, 토큰, 주문 상세처럼 민감한 값은 클라이언트 단계에서 마스킹해야 합니다. 서비스별 보관 기간도 정해야 합니다. UI는 서비스 선택, 태그·레벨 필터, 일시정지, 페이지네이션 정도로 단순하게 유지하는 편이 좋습니다.
